# 心伙伴前后端对接说明

这份文档给负责页面的前端与负责服务的后端共同使用。当前开放学生、心理教师和管理员演示端。登录和退出已经经过服务层，可切换远程接口；其他业务仍为本地演示，不会因切换认证模式自动变成真实业务。

## 接入步骤

1. 复制根目录 .env.example 为 .env.local。
2. 保持 VITE_API_MODE=mock 可直接做学生端演示。
3. 后端确认 docs/openapi.json，先实现登录、退出两个接口。
4. 设置 VITE_API_MODE=remote，VITE_API_BASE_URL 指向接口根地址，如 http://localhost:8080/api/v1，重启前端。
5. 检查成功登录、密码错误、禁用账户、网络失败、超时、退出和非学生账号。
6. 按下面清单逐个把本地业务状态迁移到服务层。

默认地址 /api/v1 需要部署平台把该路径反向代理到后端。开发时可以直接配置完整后端地址；跨域服务应允许实际前端来源以及 Authorization、Content-Type 请求头和 OPTIONS 预检。当前采用 Bearer token，不发送跨域 Cookie。若团队改用 Cookie，需要共同修改契约、凭据和 CSRF 策略。

所有 VITE_ 变量都会进入浏览器，不能放数据库密码、服务私钥或 AI 服务密钥。

## 已实现的认证通道

接口返回直接 JSON，不包 data 外层。失败使用非 2xx 状态码，返回 code、message、可选 requestId。统一请求层处理 15 秒超时、网络失败、204 和错误信息，不自动重试写请求。

POST /auth/login

请求：
```json
{"account":"S-DEMO-01","password":"仅为示例"}
```

成功 200：
```json
{"user":{"id":"真实用户ID","name":"显示名","role":"student"},"accessToken":"服务端签发的令牌"}
```

身份由后端查询账户返回，前端不提交 role。后端必须校验密码、停用状态和权限。目前前端接收学生、心理教师和管理员身份，登录类别必须与返回身份一致。后端也应按当前发布范围限制登录。

失败示例 401：
```json
{"code":"INVALID_CREDENTIALS","message":"账号或密码不匹配","requestId":"请求追踪ID"}
```

POST /auth/logout

携带 Authorization: Bearer <accessToken>，成功返回 204 空响应；后端使会话或令牌失效。前端即使请求失败也清除本机状态，并提示服务端退出未确认。

GET /auth/me

携带 Authorization: Bearer <accessToken>。有效会话返回 200：`{"id":"真实用户ID","name":"显示名","role":"student"}`（教师为 teacher，管理员为 admin）；过期返回 401，停用或无权访问返回 403。此接口用于服务端会话校验，当前前端不自动恢复登录。

每次打开或刷新应用先显示登录页，不自动恢复上一次身份。登录成功后的会话与 Bearer 凭证仅在内存保留，不写入本地存储；启动会清除旧版本当前接口模式/地址的登录记录。学校绑定与外观偏好仍保留。退出清除本机会话；尚无自动刷新令牌和完整的业务请求会话过期跳转。/auth/me 可用于后续服务端会话校验，当前启动不请求该接口；现有业务仍为演示数据。

mock 模式允许学生 S-DEMO-01、教师 T-DEMO-01 和管理员 A-DEMO-01，密码 Demo@2026；remote 模式不会回退到本地校验，也不会显示演示凭据入口。

### APP 返回行为
前端统一通过 window.campusBack() 处理最上层页面：箭头、浏览器返回、Android 容器返回及左缘右滑使用相同路径。嵌套页面逐层返回，主页面保留访问来源和滚动位置；首页与登录页消费返回事件，保持应用打开。退出登录保留专门操作。未保存内容触发原有确认，确认框上的系统返回取消离开。Android 容器现有桥接接口可直接复用，仍需真机验证。

## 学生必须绑定学校

新增 SchoolGate 作为登录后的页面边界。未绑定或查询失败时不挂载首页、底部导航和学生业务组件，只显示选校弹窗。遮罩、Esc 不能关闭；退出按钮和系统返回执行退出登录。保存失败时停留原页面，成功后才进入校园。再次显式登录会重新查询绑定学校，刷新先返回登录页。

目前开放四川航天职业技术学院，学校 ID 为 sichuan-aerospace-polytechnic。此 ID 是演示工程内部标识，不是教育部学校代码。现有校园内容仍为虚构样例，并非该校真实资料。不提供其他学校入口，也不能通过搜索输入任意学校后直接进入。

前端入口为 src/services/schools.ts，模型为 src/types/school.ts，演示存储在 src/mocks/schools.ts。mock 模式按账号独立保存学校 ID；退出登录保留绑定，清除浏览器数据会丢失演示绑定。remote 模式只接受服务端返回，不从 localStorage 推断学校。

后端需实现（见 OpenAPI）：
- GET /schools：返回当前允许绑定的学校数组，元素为 {id,name,city}。
- GET /users/me/school：返回已绑定学校对象；尚未绑定返回 200 和 JSON null，不能用 204 代替。
- PUT /users/me/school：请求仅 {schoolId}，用户身份从令牌取得，响应为成功保存的学校对象。同校重复提交幂等，已绑定其他学校返回 409。

后端必须在所有校园业务查询及写入中依据账户绑定的 schoolId 过滤并校验资源归属，不能相信客户端传入的 schoolId。未绑定账户访问校园业务应返回 403 SCHOOL_REQUIRED。绑定记录须关联用户并持久化；只可由授权流程修改，不允许学生自行换校查看其他校内容。

本次实现了前端强制绑定和单校演示，不等同于后端多租户隔离。校园墙、商家、消息等仍是本地演示模块，接入真实后端时必须逐模块落实上述校验。选校不代表在校身份认证，学号或学校邮箱验证需单独接入。

回归脚本：node qa/check-school-gate.mjs，使用 5176 预览及 9335 隔离测试浏览器。覆盖强制选校、遮罩、Esc、返回退出、搜索、绑定及刷新和重新登录。

## 心理教师业务待接入（2026-10-10）

教师 APP 页面已完成模拟工作流，认证支持服务端返回的 teacher 身份；个案、摘要、趋势、服务记录、复核结果、咨询日程、升级事项和提醒仍为本地状态。不得将此页面直接连到真实学生聊天或将前端模拟状态视为真实心理分析。

补充待接接口：预约列表/创建/改期/取消/完成/未到访，以及升级记录/接收确认。预约需要服务端检查时区、未来时间、教师时间冲突、个案状态、并发版本和幂等；取消保留历史。已完成会谈通过 appointmentId 与服务记录关联。升级事项包括校内接收角色、原因、措施、时间和确认状态；真实接收通知、未响应升级及推送送达需由服务端落实，前端“模拟确认接收”不代表他人已收到。结案需检查未结束预约和未确认升级事项，具体流转规则由学校心理中心确定。

建议契约（尚未提供真实 API）：GET /teacher/cases、GET /teacher/cases/{id}、POST /teacher/cases/{id}/review、POST /teacher/cases/{id}/records、POST /teacher/cases/{id}/close、POST /teacher/cases/{id}/reopen，以及教师提醒偏好的读取/更新。具体响应格式需先在 OpenAPI 中确定。列表支持状态、关注程度、关键词、分页；详情提供授权摘要、分析来源/时间、趋势、复核和服务记录，不返回聊天原文。工作台统计、到期回访、教师任务事件由服务端返回。

每个接口从认证会话取得教师身份，校验学校、授权、个案归属；禁止相信客户端 teacherId。复核/新增记录/结案/重开必须验证当前状态并提供版本冲突检查、幂等和必要操作留痕，日志不得含沟通、复核或辅导正文。正式结案前要求复核说明或已保存服务记录及结案依据。关注级别由分析服务提供，教师进行复核；摘要用途及授权须在学生侧明确告知。优先通知、到期通知与超时升级需由服务端可靠执行。生产环境教师账号的学校和负责范围应由管理员分配。

## 管理员端（本地演示）

登录页选择管理员，使用 A-DEMO-01 / Demo@2026。首次登录仍经过学校绑定。使用五项底部导航，桌面保持居中的手机布局；总览展示当前账号统计、身份分布、快捷入口和最近操作。

账号支持搜索、角色与状态筛选、登记、编辑显示名、确认角色变更、确认启停。当前登录账号不可停用或修改角色。已有演示账号的名称、角色、状态会影响本次访问中的后续 mock 登录；新登记账号不创建凭证。关闭未保存表单需确认。退出后账号与日志在本次访问中保留，刷新恢复样例。

角色页面说明固定的访问矩阵，角色分配在账号编辑中完成，不提供任意扩张敏感权限。管理员不接收 CareCase、心理报告或私人聊天内容。操作日志可按关键词和操作者过滤，并导出当前筛选结果为 JSON；导出动作也被记录。演示审计仅保存在内存。

remote 模式只连接认证，管理员业务仍使用本地虚构数据。生产接入至少需要：按学校授权的账号列表接口、账号创建与编辑接口、账号启停接口、服务端角色分配与可靠审计查询。所有写操作应校验管理员权限、账号学校归属和对象状态，禁止停用自身、撤销自身管理权限或移除最后一个有效管理员；停用与角色变化应同步撤销旧会话。账号创建须使用服务端凭证流程，前端不保存密码。审计事件由服务端写入，只含必要对象编号与变化，不记录学生对话及辅导正文。

### 约谈邀请与观察复核补充

已确认流程为先复核，再安排约谈或继续观察。观察保存 note / nextDate / time，到期进入教师待办；保存新的沟通跟进记录后结束观察计划。学生列表采用精简摘要，详情保留完整服务记录。

预约增加 studentAccountId、responseStatus（待确认/已接受/申请改期）、changeRequest（day/start/reason）。学生接受或提出改期，老师确认新的时间后清除 changeRequest 并将 responseStatus 重置为待确认。只有学生接受后才允许完成会谈，未结束的安排继续阻止结案。后端需按账号验证教师负责关系和学生接收关系、保存审计记录、校验未来时间与教师时段冲突，并在重新邀请时处理并发及旧邀请版本。

当前采用应用内共享的演示状态，刷新不会保存，不发送真实推送；仅 CASE-001 明确映射到 S-DEMO-01，不能使用脱敏学号推导接收账号。正式关联由服务器返回。学生响应接口不得返回风险等级、状态评估或教师内部摘要。

### 学生店铺经营权限接口

学生保留 student 角色，附加 shopManagement 权限；店铺增加 ownerId、isOpen。建议 PUT /admin/users/{id}/shop-permission（授予/收回并审计），GET /users/me/permissions，GET/POST /shops/mine，PATCH /shops/mine，POST/PATCH /shops/mine/products。订单状态接口校验当前学生具有经营权限且是店铺 owner，购买仍走学生订单接口。限定同学校账号与店铺；每名学生只创建一间店铺。角色转为非学生、账号停用或收回权限后拒绝所有经营操作和店铺新订单；保留历史数据，再授权恢复。价格以整数分存储，库存与订单更新须事务处理。前端现为共享内存演示，不提供真实权限持久化或服务端鉴权。
管理员店铺治理：建议 PATCH /admin/shops/{id}/moderation，维护独立 adminSuspended 标志并审计；服务端订单创建须拒绝被暂停的店铺。店主更新资料接口不能写此字段。解除暂停不自动授予开店权限、不修改店主营业设置，不删除历史订单。
校园通知与反馈：GET/POST/PATCH /admin/notices，GET /notices（仅本校已发布）；POST/GET /feedback/me，GET/PATCH /admin/feedback/{id}（状态和回复）。服务端按学校、账号、角色校验范围，学生只能访问自己提交的反馈，管理员仅处理本校反馈。通知草稿/撤回不得进入学生列表。管理员记录发布、撤回、处理、回复操作。当前前端共享内存实现了两端联动，真实持久化、鉴权和推送尚待接口接入。
学生回应约谈：建议 GET /appointments/me，POST /appointments/{id}/response，支持 accepted / reschedule_requested / declined，携带改期请求或婉拒说明。服务端必须按学生与教师绑定关系鉴权、检查有效时间和状态，防止重复回应；重新邀请清除旧改期/婉拒说明并恢复 pending。当前前端状态为共享内存，不发送真实推送。

## 帖子举报与违规审核

学生帖子详情的举报会进入管理员「反馈处理 → 帖子举报与违规审核」队列。按帖子聚合举报，单账号单帖只能举报一次，累计 3 个不同账号的未处理举报标记为优先审核，不自动删除。管理员可筛选待审核、优先审核、全部公开帖、已删除，也可主动审核未被举报的公开帖。

保留或删除都必须填写审核说明并确认。保留会关闭现有举报，新的举报人可触发后续审核；删除会关闭举报并从共享帖子源屏蔽该帖，校园墙、热门推荐、搜索、地点分享、收藏及足迹列表均不再返回删除内容。已删除记录仅供管理员查看，保留原因、操作者、时间和帖子证据，不展示举报者身份。操作记录只写帖子编号及操作类型，正文与审核说明留在审核记录中。

共享状态由 CommunityProvider 维护：公开帖子、举报与审核记录在退出与切换身份后保留到刷新；非公开帖子仅作者可见且退出时清空，不进入管理员队列。当前仍为单次页面访问内的演示，刷新恢复样例，不支持跨设备或跨浏览器同步。

服务端接入需提供同校公开帖列表、举报创建与唯一约束（学校/帖子/举报者）、按帖子聚合的审核队列、带原因的审核写入与审计、删除屏蔽及证据保留。管理员写操作须检查当前有效角色、学校归属和帖子状态；举报次数仅为复核优先级。删除屏蔽须应用到所有查询与详情接口，服务端事务内关闭举报并记录审核及审计，不能仅由前端隐藏内容。
